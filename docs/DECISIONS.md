# Decisions

Running log of architecture and product decisions. Newest first.

## 2026-10-23 — Integration

- **A conversation-style profile of the user, inferred from words only.** `personality_profiles` holds eight 0..1 trait scores, humor styles, topics, repeated expressions, pace and notes, built by `analyzeStyleHeuristic` at conversation end (plus the cheap text model for live conversations, with the heuristic as a hint and an explicit ban on health, finances, grief, family conflict and protected characteristics). The Realtime API gives the app transcripts, not prosody, so nothing is inferred from audio and every surface says "inferred from your words, not your voice". Scores merge by EMA with weight `max(confidence × 0.5, share-of-evidence × 0.5)` capped at 0.5, so one conversation never flips a profile. The prompt block (≤ ~120 tokens) appears only with memory on and ≥ 6 messages of evidence; the demo brain uses the same profile to step gentle humor up to playful's quip rate (humor ≥ 0.6) and to prefer "long version" templates (verbosity ≥ 0.6). Covered by memory consent; viewable and resettable from the memory page; exported; cascades with account deletion.
- **Three-channel listening (what / how / why) with an honest split between modes.** `tone_events` records per-turn tone (humor, warmth, frustration, upset, anxiety, confusion, fatigue, joy, neutral), intensity, intent (venting, seeking information, wanting company, reminiscing, asking for help, seeking reassurance, joking, planning, small talk) and a short cue. In live mode the *model* hears the voice and reports through the new `observe_tone` tool (source `model`); in demo mode `classifyTone` infers from lexical cues (source `heuristic`). The tool never changes the saved humor preference: on distress (≥ 0.6) or an explicit `serious` flag it tells the model to drop humor and slow down for this conversation only. Tone events are stored only with memory consent; without it the tool still answers behaviourally and stores nothing. Reset deletes them with the profile. The system prompt gained a "# Three-channel listening" section, raising the no-memory budget test from 1,800 to 1,900 tokens (measured worst case 1,885).
- **Demo transcripts show `observe_tone` only for notable turns.** Every user turn is classified and (with memory on) stored, but the transcript tool entry appears only when the tone is non-neutral at intensity ≥ 0.5, so routine turns are not cluttered with "Listening to how you sound…" chips and existing tool-call expectations hold. The one existing test that asserted an empty tool list on a bereavement turn now expects the `observe_tone` entry.
- **Web search is on by default (opt-out).** Only the model's query string reaches search, never memories or the name, so there is nothing private to protect with an opt-in; the switch stays in Settings for billing control. `hasConsent("web_search")` returns true when no record exists; memory scopes remain opt-in.
- **Side-by-side comparison hidden** behind `NEXT_PUBLIC_COMPANION_ENABLE_COMPARISON`; it is an economics tool for later and double-bills.
- **In-app cost caps relaxed to $20/day and $10/user/day.** The OpenAI account has its own monthly limit; the app caps are a backstop, not the budget.
- **Model IDs are `gpt-realtime-2.1` / `gpt-realtime-2.1-mini`,** transcription `gpt-realtime-whisper`, text `gpt-6-luna`. The names in the original brief (`gpt-realtime`, `gpt-realtime-mini`) are deprecated with a 2027-01-20 shutdown; verified in `docs/API_VERIFICATION.md`.
- **Transcript rehydration ignores memory consent.** `buildMemoryContext` gates stored facts and summaries on memory consent, but always includes the tail of the conversation being continued: that transcript is the live conversation, not memory, and a model switch must not amnesia the user who declined memory.
- **Demo brain callbacks speak in the second person, or quote.** Stored memories are statements about the user; a heuristic converter rewrites them ("you tend a garden… your pride"). Subject pronouns are left alone for memories about other people (family, friends, stories) because "he is a beagle" is about the dog. When the result does not start with "you/your", the brain quotes the note rather than mangling it.
- **Malformed ids are 404s.** Route ids are UUID-checked before hitting Postgres so a bad id cannot surface a database error.
- **E2E runs start from a truncated, re-seeded test database** (`scripts/e2e-reset.ts` via Playwright `globalSetup`). Tombstones are deliberately persistent, so a previous run's deletions would otherwise block a later run's saves.
- **Demo sign-in has its own rate-limit bucket** (30/min/IP) separate from password auth (10/min/IP): there is no password to brute-force and shared devices sign in often.
- **An explicit, confirmed save supersedes a tombstone; nothing automated does.** `rememberMemory(..., userConfirmed: true)` (the memory page, a spoken "remember that…", a tool call with `user_confirmed: true`) retires the tombstones the statement matches, logs `memory_events.corrected` with `{ retiredTombstones, reason: "user_confirmed_supersedes" }` and saves the fact as `confirmed`. Unconfirmed model saves, summarizer candidates and summaries stay blocked exactly as before. Consequence, by design: once a correction ("Lily plays the cello") retires the "violin" tombstone, a later candidate about the old fact is no longer blocked — the confirmed fact is the user's latest word. Names are never tombstone keywords: the user's preferred name and the demo display names are excluded from tombstone creation, matching and summary-sentence redaction, so "Margaret prefers tea" and "Margaret talked about her mornings" share no keyword.
- **Summaries carry a sensitivity label and respect sensitive consent.** `storeSummaryMemory` classifies the text with the same keyword classifier the demo brain uses (`src/lib/memory/sensitivity.ts`); sensitive summaries are injected only with sensitive consent, the heuristic summary drops sensitive statements without it, and the AI summarizer is told to omit health, finances, grief and family conflict entirely.
- **No paid summarization for demo conversations or when memory is off.** `finishConversation` calls the text model only when the conversation is live and memory is on; otherwise the heuristic summary is used (and still stored only when memory is on).
- **Usage events outlive the account.** `usage_events.user_id` is nullable with `ON DELETE SET NULL` (migration 002): deleting an account removes the person's data but not the operator's spend, so the global daily cap cannot be reset by deleting and re-creating accounts. Per-user usage views filter by `user_id` and never show anyone else's rows.

## 2026-10-22 — Foundation

- **Next.js 16 App Router, Cache Components disabled.** Every page is auth-gated and dynamic; PPR/`use cache` adds complexity for no benefit in an MVP. Can be enabled later per route.
- **Plain SQL migrations + `pg`, no ORM.** Schema is small and explicit; hand-written SQL keeps per-user scoping visible in every query, which is the main security property we must be able to audit. Migration runner is ~60 lines (`src/lib/database/migrate.ts`).
- **Stateless signed session cookie (jose, HS256) + `token_version` on users.** No session table needed; bumping `token_version` revokes everything. Demo profiles use the same mechanism with `is_demo = true`.
- **Demo mode runs a server-side "demo brain" against the same memory store.** This lets memory consent, recall, correction and model-switch rehydration be exercised and tested without any paid API, and is labeled *Simulated* everywhere in the UI.
- **Memory deletion uses tombstones + summary suppression.** Deleting a memory writes a `memory_tombstones` row with its normalized text and keywords. Retrieval filters any summary containing tombstoned keywords, and extraction refuses to re-create a fact matching a tombstone. Summaries are additionally redacted/regenerated on delete. This is how "deleted facts are not restored from summaries" is enforced rather than hoped for.
- **Provenance labels are a one-way street.** `inferred -> confirmed` only via an explicit user action (UI confirm or a spoken yes captured as a `record_consent`/`remember` tool call with `user_confirmed: true`). The API refuses other status changes.
- **Pause sensitivity maps to Realtime `semantic_vad.eagerness`** (patient = low, balanced = medium, quick = high) with `server_vad` as a fallback option. Semantic VAD is chosen because older adults with hesitant speech are the primary users.
- **Fred and Ethel** are the two companion voices (male-leaning and female-leaning OpenAI voices). The persona name shown and spoken follows the selected voice. OpenAI does not label voice gender; the assignment is ours and documented in `src/lib/ai/models.ts`.
- **Web search via OpenAI Responses `web_search` tool, server-side only.** Same vendor, same key, citations returned as `url_citation` annotations and shown in the transcript. The Realtime model calls our `search_web` function; the server runs the search and never includes memories in the query.
- **Hosting:** the development container has no public URL. Target: Vercel (app) + Supabase Postgres (data), deployed only with the user's tokens and explicit approval. See `PREVIEW.md`.
